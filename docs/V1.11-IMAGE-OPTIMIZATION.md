# Image optimization v1.11

Browser uploads are resized and re-encoded when that reduces transfer size, including files below the old 2.5 MB threshold. The API independently decodes JPEG/PNG/WebP, rejects invalid/animated inputs, caps decoded pixels at 40 million, applies EXIF rotation and strips embedded metadata. WebP output is capped at 1280 pixels / 250 KiB for details and 400 pixels / 45 KiB for thumbnails. Difficult images use lower quality or dimensions to meet those byte caps; small images are not upscaled.

Migration 008 adds nullable thumbnail object keys and byte counts. Search, provider listing and similar-listing cards use thumbnails through the shared API, benefiting web and mobile without an Expo update. Web gallery previews use thumbnail URLs; the selected image uses the detail variant. Existing lazy loading and pagination remain.

Each upload writes new private object keys. A single SQL statement atomically upserts the batch only after every object upload succeeds. Failed storage writes clean up only the new objects. Replaced objects are retained, and objects whose database commit status is uncertain are retained for later reconciliation; no existing object is deleted automatically. Old presign/confirm upload endpoints now return 410 for authenticated providers, preventing bypass of server validation. The active browser uploader already uses upload-direct.

Re-upload existing images to generate variants, including the earlier 747 KB image. No automatic bulk rewrite is performed. The native provider UI still has no image picker; use the web provider portal for uploads.
