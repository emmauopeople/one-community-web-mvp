# Web/mobile service-detail parity

Web service details now follow the mobile hierarchy: gallery arrows, image counter,
thumbnails and enlargement; service title/locality; provider-account label;
description; provider-profile link; gradient WhatsApp action; separate email inquiry;
and four similar listings from the same category, excluding the current service.

Provider profiles expose paginated provider listings and the same **Reviews coming
soon** copy as mobile. Neither app has published reviews or a review-submission API
yet. This revision does not invent reviews, ratings or approval claims.

Back returns one step through provider profiles, listings and inquiry; Close returns
to the search results. The modal contains keyboard focus, supports Escape, restores
focus and page scrolling on close, and preserves earlier views while navigating.
Related-list failures keep the current service readable with a retry action.

Get started uses the exact mobile title and four heading/paragraph pairs. The help
copy was checked against the current mobile source during browser verification.

The API detail endpoint already records skill_view. The old duplicate client event
is removed; contact events contain the skill ID/channel, not inquiry contents.

Validation: production build and browser checks at 390px/1280px pass for gallery,
thumbnails, enlargement, inquiry payload/submission, provider pagination, review
placeholder, similar navigation, Back/Close/Escape, focus trap/restoration, related
error recovery, exact help text and absence of a duplicate browser skill_view event.
API/weather/contact requests were mocked for those UI checks; live contact delivery
still requires local acceptance. No dependencies, API contracts or schema changed.
