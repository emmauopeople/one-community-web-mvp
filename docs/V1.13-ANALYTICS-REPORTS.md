# Admin analytics and printable reports

The admin UI uses the separate admin-api, not the skill-api analytics routes. Its original seven endpoints existed; the new `/api/admin/analytics/report` consolidates business analytics into one authenticated, non-cacheable SQL snapshot. Existing endpoints remain for compatibility.

Select 7, 14, 30 or 90 calendar days including today in Africa/Douala (UTC+1). All panels and the printed report share the same bounds and generated timestamp. Future events and events before the first midnight are excluded. Daily rows include zero-activity days. Current and legacy contact event formats count toward the same contact totals. Ratios describe event activity, can exceed 100%, and are not visitor conversion or confirmed bookings.

Search pagination no longer creates extra search events. Email contact events are recorded after successful server mail submission for both apps; client email events are rejected to prevent duplicate counting. Mobile WhatsApp records best-effort contact intent after opening the link. Email counts indicate mail submission, not delivery to the recipient's inbox; WhatsApp counts do not prove a conversation occurred. Historical missing mobile contacts cannot be recovered. Offline event buffering/deduplication by persistent event ID remains future work.

In Business Analytics, choose English/French and a period, then **Print / Save PDF**. The browser print dialog supports a printer or Save as PDF. The report contains summary metrics, ratios, cities, categories, channels, top listings and all daily rows. Navigation and login logs are excluded. Printing is disabled during loading or errors and stale responses are ignored. This is browser print-to-PDF, not a server PDF download. No new library or database migration is needed.

Validation: seeded PostgreSQL-WASM report totals, boundaries, zero-filled 90-day range, legacy contacts and authorization; real email route with mocked mail transport; pagination regression; bilingual browser print checks and visual review of multipage A4 PDF fixtures. Run the supplied v1.13 local sync/test script to rebuild Docker and restart Expo before local acceptance.
