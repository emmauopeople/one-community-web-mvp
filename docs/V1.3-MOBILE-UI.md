# Mobile experience v1.3

The current plan is `One_Community_Phase1_Upgrade_Implementation_Plan_v1_3.pdf`.
Its first page revises the mobile UI; the remaining pages preserve the v1.2 baseline.

Home now has one search field, a gradient Search action, and a compact optional
Use location switch below it. The top-right menu puts Provider first, followed by
expandable categories, distance (10 km by default; custom 1-100 km), and About.
General guidance lives in About. No new app dependency was added.

Registration collects first name, last name and optional business name separately.
The operating-region dropdown contains the ten Cameroon regions. Mandatory GPS
consent/capture/confirmation is unchanged. Back returns one step; Close returns
to search. Primary buttons share the search gradient; secondary actions are blue.

Deploy the matching web feature with migration 004 before testing registration.
The migration adds nullable name fields without guessing existing users' names.
The API validates the structured fields and persists them through OTP completion.
Older displayName-only web clients remain supported during this mobile change.
Public display name prefers business name, otherwise the combined personal name.

Validation: six mobile tests, 17 web migration/API tests, Android JavaScript export,
and phone-width browser interaction checks using React Native Web with stubbed
GPS/API/Expo adapters. Browser checks cover menu, categories, 10 km, custom-radius
validation, permission denial, region, consent gate, Back, Close and About.
Full Hermes export is checked in CI. Physical Expo Go testing is still required.

No release/main merge or deployment is authorized by these checks.
