# OVH private image storage

Paris region: `eu-west-par`. Endpoint: `https://s3.eu-west-par.io.cloud.ovh.net`. Bucket: `one-community-storage`. Keep the bucket private.

Run `node scripts/setup-storage.mjs` once, then edit `.env.storage` locally. Enter the S3 **access key ID** and **secret access key**. The OVH user name is not the access key. The file is ignored by Git, excluded from Docker build contexts and supplied only to the skill API container. Do not run a non-quiet Compose config command or share environment output. Use independently managed production credentials when deploying to OVH.

Recreate the API using the same Compose files used to start the stack, for example `docker compose up --build -d skill-api`. Include your Wi-Fi override when used. Then run:

```bash
docker compose exec -T skill-api node scripts/check-storage.mjs
```

The check uploads a uniquely named, tiny PNG under `_checks/`, verifies a signed download and denied anonymous access, and deletes only that check object. It needs object Put/Get/Delete permissions. If bucket versioning is enabled, the provider may retain a noncurrent check-object version. No live storage verification is possible until the local credentials are entered.

Existing browser uploads pass through the API; no bucket CORS change is required for this upload path. Signed GET links display private images on both public web and mobile. Links expire after 15 minutes; refresh the listing to obtain a fresh link. Existing object keys and database records are preserved. Configuration does not populate images for listings without uploaded files.

After the check passes, sign in on the provider web portal, edit a skill, select an image and upload. Check its listing card and detail gallery on web and Expo Go. The native provider screen does not yet contain an image picker; images uploaded through the web are visible in mobile discovery. Optimization/thumbnails and low-bandwidth acceptance follow separately.

No database migration is required. Endpoint and credentials stay in environment configuration when moving the API to OVH. Reference: https://docs.ovhcloud.com/fr/guides/storage-and-backup/object-storage/s3-location
