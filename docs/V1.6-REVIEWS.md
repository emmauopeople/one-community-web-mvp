# Phase 1 v1.6: moderated reviews and restrained typography

Reviews submitted from service details or a provider profile enter a pending queue. An active administrator must record verification notes and confirm verification before approving publication. Rejection and returning an approved review to pending also require notes. These actions are version checked and audited atomically.

Only approved reviews contribute to public lists and rating totals. Contact emails and internal notes are private to administrators. Provider visibility/consent checks also apply to reviews. No automatic email verification or purchase verification is claimed. One review per email/provider limits duplicates; this pilot rule can be revisited with authenticated reviewer accounts. Public submission is limited to 30 requests per 15 minutes per observed IP (reverse proxies can share this limit).

Web and mobile expose the same submission fields: display name, private email, rating, review and publication consent. Lists fetch 10 reviews at a time; no polling or new runtime dependencies. Review bodies/emails are not sent to client analytics. Admin status counts and audit records support pilot monitoring.

Titles use semibold weight and restrained sizes: approximately 17–20 on mobile, up to 20px on web, with smaller card titles. Buttons retain their existing primary/secondary treatments.

## Local acceptance

1. Rebuild the web Docker stack, including the migration/tools image. Migration 005 adds provider_reviews without changing existing data. Keep volumes; do not use down -v.
2. Open a service on web and mobile. Submit a review with publication consent. It must remain absent publicly, with no change to rating totals.
3. Sign into the admin portal and open Reviews. Check the contact and review manually, add verification notes and tick verification. Approve becomes available only then.
4. Refresh public reviews: the approved review and rating appear, but private email/notes do not. Test Reject and Return to pending; refresh removes the review and totals.
5. Test provider-profile reviews, pagination, a duplicate email, malformed input, offline error/retry, Back/Close, and title readability on your phone.

## Validation

25 root integration/migration tests passed, including PostgreSQL-backed review lifecycle, private-field allowlisting, anonymous/inactive-admin denial, duplicate/invalid input, provider consent withdrawal, version conflict, audit rollback and approved-only pagination. Existing service/admin tests also passed (18). Mobile utility tests: 6 passed. Public/admin production builds and mobile Android JavaScript export passed locally. Browser interaction checks covered web submission/admin approval/unpublish, gallery/provider/similar-listing navigation, exact mobile Get started copy, mobile review form and small-screen layout. Mobile interaction checks used React Native Web; physical Expo Go acceptance remains required. Local Docker execution is performed by the user.
