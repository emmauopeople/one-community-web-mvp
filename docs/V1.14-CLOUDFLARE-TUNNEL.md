# servicecam.org public test tunnel

Create a remotely managed Cloudflared tunnel named **servicecam-mvp** in Cloudflare Networking > Tunnels. Select Docker. Copy only the token after `--token`; do not paste it into chat, Git or a command with a visible token. Run `bash scripts/tunnel-up.sh` from Git Bash. Its hidden prompt stores the token in ignored `.env.tunnel-token`. The connector image is pulled once and its immutable digest saved in ignored `.env.tunnel-image`. Neither file enters Docker build contexts.

Add a Published application route: domain `servicecam.org`, empty subdomain/path, type HTTP, service `tunnel-gateway:8080`. Cloudflare creates the DNS record. The origin is an internal Docker service; do not use localhost in the Cloudflare route. The connector must show Healthy. Run `node scripts/tunnel-check.mjs` after DNS is ready.

The public website is `https://servicecam.org`. The mobile API base is `https://servicecam.org/api`. To test with Expo: `EXPO_PUBLIC_API_BASE_URL=https://servicecam.org/api npm start -- --clear --go`. This does not change the saved local .env. Expo's QR/Metro connection remains a separate development connection; the Cloudflare tunnel only serves the website/API. The future APK will not require Metro.

Secure cookies require provider login through HTTPS while the overlay runs. Sign in again after changing origins. Admin remains `http://localhost:8081`; Mailpit remains local. The gateway excludes admin, metrics and health routes, accepts only servicecam.org, and replaces forwarded protocol/IP headers. Cloudflared connects only to the dedicated gateway network; no host ports, Docker socket, or database ports are added. The connector uses a read-only filesystem, no Linux capabilities, and root only to read the owner-only mounted token file.

This is a PC-hosted pilot: Docker Desktop, the PC and Internet connection must remain running. SMTP is still Mailpit, so external account verification and inquiry delivery require a real SMTP provider before general user onboarding. No database volume is deleted or reseeded by these scripts.

Stop public access: `CLOUDFLARED_IMAGE=$(cat .env.tunnel-image) docker compose -f compose.yaml -f compose.tunnel.yaml stop cloudflared`. Restore local HTTP provider login: stop cloudflared and tunnel-gateway, then `docker compose -f compose.yaml up --build -d`. Reapply the optional Wi-Fi override when returning to LAN testing. Future updates must include `-f compose.tunnel.yaml` (with CLOUDFLARED_IMAGE loaded from .env.tunnel-image) or use tunnel-up.sh so HTTPS settings remain enabled.

Validation: secure cookie round-trip and YAML isolation tests; Docker CI runs the gateway without Cloudflare credentials and tests website/API routes and private-path denial. Actual Cloudflare connectivity and phone acceptance require the user's tunnel token and published route.
