# Public home v1.4

The public home and /search share a mobile-first layout matching the mobile app:
brand header, top-right Provider/Categories/Distance/Get started menu, one search
field, gradient Search action and compact optional location switch. Nearby starts
at 10 km. The retired landing component now delegates to SearchPage, removing its
popular-category card and duplicate search/weather flows.

Weather is above service listings. Services load immediately, independently of
weather or pending GPS. Weather starts with explicitly labelled Douala; visitors
can select a city, or share location through the search switch. Weather coordinates
are rounded to two decimals; forecasts are cached in session storage for 15 minutes.
Requests time out after eight seconds and fail without blocking service discovery.
No new dependency is added. Open-Meteo attribution remains visible.

The v1.4 PDF revision takes precedence over earlier public-home layout requirements.
Provider consent, API contracts, and listing visibility rules are unchanged.

Validation: production build passes (108.92 kB gzipped JS). Phone-width (375px) and
desktop (1280px) browser checks with mocked API/weather pass: immediate listings
while weather waits, weather success/failure, city selection, category filtering,
location toggle, default/custom radius, Get started and no horizontal overflow.
Rebuild public-web locally and test the real weather connection before acceptance.
