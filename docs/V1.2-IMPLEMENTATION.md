# Version 1.2 - provider consent and nearby discovery

The authoritative plan is `One_Community_Phase1_Upgrade_Implementation_Plan_v1_2.pdf` beside this file. It supersedes earlier per-listing GPS consent and optional provider GPS wording.

## Implemented in this feature

- Web and mobile provider onboarding require an unchecked-by-default consent, fresh operating-location capture, confirmation and email verification. The server rejects missing consent at registration begin and completion.
- Existing providers have location setup and withdrawal controls. New skills inherit the saved location without fresh GPS. Existing listing snapshots do not move silently when the profile changes.
- Public web is mobile-first and listing-led. The old category-card landing page is no longer mounted; categories remain an optional compact filter.
- Public web/mobile share one paginated search endpoint, 12 results per page, default 20 km and a maximum 100 km radius. Nearby is opt-in, with manual/general search fallback. Public responses and analytics exclude exact coordinates.
- Mobile includes provider registration/login, default location management and basic skill creation. Remaining mobile edit/media tools, moderation, complete EN/FR and shared identity extraction remain their own roadmap work.
- Nearby state lasts for the mobile session; web remembers only the opt-in preference, not coordinates. Cross-launch mobile preference persistence remains a follow-up.
- Region is a controlled list. Division is validated free text in this slice; the controlled division/subdivision dataset remains planned.

## Upgrade and acceptance

Migration 003 adds fields without deleting data or silently accepting consent. Real existing providers must sign in and complete operating-location setup. Public visibility requires current consent after this feature starts. Review this cutover before deploying to real users. Synthetic fixture consent is clearly simulated and restricted to the named local seed account.

Run root `npm ci`, `npm run install:apps`, `npm test`, `npm run test:legacy`, `npm run build`, then the Docker startup script. Root integration tests use the real Express routes and PostgreSQL WASM; app dependencies must be installed first.

On the PC use http://localhost:8080 for browser GPS. Mobile browsers opening plain HTTP on the Wi-Fi IP cannot use browser geolocation; use Expo or HTTPS. The phone's Expo API URL remains in its untracked .env.

No feature/release/main merge or public deployment is authorized by this file. Test locally before release merge.
