# Phase 1 amendment: community feedback

The public website and mobile discovery screen have small About, Report issues and Your opinion links. About describes the goal of connecting people with local service providers in Cameroon. Get started remains the existing tutorial.

Reports support app problems, suggestions, application comments and provider problems. Subject is 3–180 characters and description 10–3000. A usefulness answer is optional on reports. No account, name or phone number is required. Email is optional and stored only with explicit permission to contact the submitter.

On submission, reports with Include GPS location selected request device permission and capture location automatically. Coordinates are rounded to three decimal places and visible only to admins. Reports remain available without GPS when permission is declined, the device cannot locate, or the user deselects the option. No IP geolocation fallback or background tracking is used. GPS collection applies to reports, not the short usefulness survey.

After scrolling to the bottom, the discovery screen asks whether the application can help people in Cameroon. Yes/No opens a comment form; X dismisses it. The automatic prompt is shown once per browser/app installation using local storage. Your opinion can reopen it. Comments are optional. This is voluntary feedback, not a unique-person poll or a representative measure of Cameroon adoption. Clearing app/browser storage can allow the prompt again.

Migration 009 creates public_feedback and feedback_replies without modifying existing support threads or deleting data. Both channels use POST /feedback with request IDs for safe retries, bounded fields and per-IP rate limiting. Public responses expose no stored contact/location information and there is no public feedback read endpoint.

Admin > Community feedback lists reports and surveys, filters by type, displays channel/language/location and survey Yes/No totals, and supports New/In progress/Resolved states. The API requires a currently active admin. Status changes and replies are audited. Email replies are available only for consenting submitters. Reply history distinguishes accepted mail, pending and unconfirmed delivery. A repeated reply request ID never sends twice. Delivery failures are never automatically retried; inspect history before composing another reply.

Until SMTP is configured, replies are captured in local Mailpit. The UI explicitly reports this; no external email delivery is claimed. Once real SMTP is configured, server acceptance still does not guarantee inbox delivery. User-written reports and replies retain their original language; interface labels are English/French.

## Acceptance checks

1. On web and mobile, open About and confirm that the separate Get started tutorial remains unchanged.
2. Submit an anonymous report with each category; deny GPS once and allow it once. Confirm success and the corresponding admin location state.
3. Enable email contact, submit a valid email, and verify that only this report offers an admin reply. Inspect the reply in local Mailpit while SMTP remains local.
4. Scroll to the bottom: close the usefulness prompt, navigate away/back, and verify it does not automatically reappear. Use Your opinion to submit Yes and No with optional comments.
5. Switch English/French, including while a form is open. Check long text at narrow phone widths and retry after a network interruption.
6. In admin, filter reports/surveys, inspect totals, change status and inspect reply history. Anonymous admin requests must return 401.

No release/main merge or OVH deployment is included. Apply migration and rebuild the PC stack with both compose.yaml and compose.tunnel.yaml so HTTPS cookies and the running tunnel are preserved.
