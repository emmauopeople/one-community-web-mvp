# Separate provider skill views

My skills is the default list. Desktop/tablet web uses two columns; phone web and the mobile app use one column. New skill opens a clean creation form. Edit opens only the selected skill, retaining its saved location. Back returns to My skills; Android hardware Back follows the same rule. A failed save preserves the draft for retry.

Web creation stays in the form after saving so the existing image uploader remains available. Back shows the refreshed list. Mobile saves return to My skills. No new GPS capture is introduced and existing API ownership/consent rules continue to apply.

Acceptance cases: list starts without a form; 2/1 responsive columns on web; create then Back shows the saved skill; edit updates the selected skill without relocation; failed save retains inputs; new form after editing is blank; Back never closes the provider area from a skill form. Physical-phone acceptance is still required.

Validation: web browser and React Native Web interaction checks passed all these form/navigation/save cases; mobile utility tests passed including skill-form back navigation. Web production build and Android JavaScript export passed. The implementation plan v1.7 records the change. No database migration is needed for this revision.
